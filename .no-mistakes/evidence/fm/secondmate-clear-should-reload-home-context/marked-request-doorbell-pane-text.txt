# The doorbell a secondmate actually receives in its pane

Driven through the real bin/fm-send.sh with a tmux that records the literal
keystrokes; the text below is byte-for-byte what was typed into the pane.
The request payload itself never gets typed - it rides the durable inbox record -
so the doorbell is ALL a freshly /clear-ed mate has to go on.

## Marked from-firstmate request to the devops SECONDMATE  (fm-send.sh fm-devops "audit the release build")

--- BASE  (43ead08, before the fix) ---
Firstmate instruction waiting: list /tmp/fm-ev-doorbell/base-home/state/devops.inbox/*.msg and, in numeric order, read and act on each, then mv each handled file to /tmp/fm-ev-doorbell/base-home/state/devops.inbox/handled/.

--- FIXED (5900b2e, this change) ---
Firstmate instruction waiting: list /tmp/fm-ev-doorbell/fixed-home/state/devops.inbox/*.msg and, in numeric order, read and act on each, then mv each handled file to /tmp/fm-ev-doorbell/fixed-home/state/devops.inbox/handled/. Each is a from-firstmate request: after doing it, append one status line that includes its corr=<id> token (shown in the request) to /tmp/fm-ev-doorbell/fixed-home/state/devops.status - the main firstmate reads only that status file, not this pane, so a reply only here is lost.
